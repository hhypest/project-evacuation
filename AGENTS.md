# Правила работы агентов

Действуют для всего репозитория, пока вложенный AGENTS не уточняет локальные правила. Прямое поручение владельца имеет приоритет. Для задачи по документации не создавать игровой код без необходимости.

## Перед работой

1. Проверить ветку, текущие файлы и чужие изменения. Не стирать чужую работу.
2. Прочитать [Readme](Readme.md), [status](docs/status.md), [roadmap](docs/roadmap.md), [архитектуру](Architecture.md) и документы затронутой области из [каталога](docs/README.md).
3. При продолжении выбирать ближайшую незавершённую задачу с выполненными зависимостями; не просить повторить существующий план.
4. Различать требование, принятое решение, предложение и свидетельство. Доводить согласованный сценарий до результата; заглушка и обещание не заменяют реализации.

## Неизменяемые рамки


- Godot **4.7.x Standard**, строго типизированный **GDScript**.
- Графический API **Vulkan**; основной метод — **Forward+**. Зелёная проверка на OpenGL/D3D12 не заменяет проверку Vulkan.
- Встроенный **Jolt Physics** для 3D. Не подключать одновременно другое расширение физики и не переключать backend для обхода ошибки.
- **DDD и Clean Architecture** с направлением зависимостей из Architecture.
- Сохранения прогресса — **JSON UTF-8** с `schema_version`, проверкой входных данных и явной совместимостью. JSON-кодек находится в Infrastructure; Domain/Application работают с типизированными снимками через порт хранения.
- Финальный интерфейс — **диегетический**: информация и элементы управления имеют носитель в игровом мире, доступный герою. Это касается также проектирования меню/паузы. Текущая техническая оболочка и прицел временные; не принимать их как финальное UI и не менять уже согласованную политику паузы/фокуса ради оформления.
- **MIT** для собственного кода и документации; собственные ассеты включаются с явно определённой областью лицензии, внешние — со своими условиями.
- Полностью бесплатное прохождение и самостоятельный офлайн-запуск. Steam — будущая площадка, а не обязательный сервис игры.
- Первое лицо, физические головоломки с хоррором, далёкое будущее, герой — белый мужчина-человек, место — инопланетная мегаструктура на агрессивной планете, цель — эвакуация.
- В 0.1.0 должны быть **все** базовые механики из требований, включая вид и физическое прохождение через порталы. Сложную механику нельзя молча отложить до другого релиза.

Смена стека, отказ от заявленной механики или добавление платного контента требуют явного пересмотра требований. Рутинный выбор реализации, обратимые исправления и локальные проверки выполняются в рамках поставленной задачи без повторного согласования.


## Обязательные правила по области

- [Правила кода](docs/development/coding.md) — типы, DTO, динамические границы, имена и предупреждения.
- [Архитектура](Architecture.md) — направление зависимостей, владение состоянием, scope/tick и границы Godot. Изменения зависимостей, фаз, схемы сохранения, портальной математики или backend оформлять ADR.
- [Физические изменения](docs/development/physics.md) — ввод, контакты, перенос, гравитация, порталы и восстановимость.
- [Права и контент](docs/development/assets.md) — происхождение, лицензии, импорт, кэши и исходники.
- [Проверки](docs/development/checks.md) — основной источник команд и критериев. Импорт, типы, CPU, GPU и прохождение — разные свидетельства; не подменять одно другим.
- [Сопровождение документации](docs/maintenance/README.md) — основной источник каждого правила, обратные ссылки, состояние и история.

Правила в этих документах обязательны для затронутой области, а не рекомендованное чтение. Минимальное изменение доводит полный сценарий: правило → application → адаптер → сцена/UI, когда они нужны.

## Канон и художественные источники

Канон — [библия ART-01](docs/design/lore/world-bible.md); при расхождении верна она. [Подтверждённый R1](docs/design/lore/archive/pre-bible-checklist.md) — происхождение решений, [редакция 4](docs/design/lore/outline-v4.md) — художественный текст. Черновики и гипотезы персонажей не равны канону.

Приняты мягкие кислород/радиация без таймеров в камерах, фонарь без заряда, один маршрут с финальным решением и двумя вариантами сцены, ориентир 8–10 часов. Реализация этих систем планируется отдельно. Перестройка помещений, вспышки памяти, протокол носителя и подписи PDF не создают новых поручений. Визуальное направление — [ADR-0006](docs/adr/0006-art-direction.md), применение — [руководство по арту](docs/design/art-production-guide.md).

## Завершение

Выполнить релевантные проверки и [Definition of Done](CONTRIBUTING.md#10-definition-of-done), обновить status и changelog по свидетельствам, проверить diff, ссылки и секреты. Если нужного инструмента/GPU/платформы нет — сделать доступное и точно указать остаток. Не создавать тесты, повторяющие строки реализации.

Публикация, платежи и договоры не следуют автоматически из разработки. Подготовить проверяемый результат; внешнее действие выполнять при наличии поручения. Не отправлять сообщения другим людям от имени владельца без прямого поручения.

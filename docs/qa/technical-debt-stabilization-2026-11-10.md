# Стабилизация TD-01…07 — 2026-11-10

Основание: [аудит](../maintenance/architecture-audit-2026-11-10.md), поручение владельца «Приступай к выполнению». [Решение ADR-0014](../adr/0014-physical-observations-and-portal-recovery.md).

## Результат

- AUD-01: нагрузка по направленным контактам Jolt, а не касанию; бок плиты и бок верхнего куба не нажимают. Верх, стопка, удаление и повёрнутая плита учитываются корректно.
- AUD-02: возврат перед порталом проверяет полную форму и путь; последняя свободная поза не разрешает обход новой стены. Если возврата нет, текущий scope останавливается и Bootstrap перезапускает всю камеру с новым поколением. Несохранённое текущее состояние камеры сбрасывается; checkpoint появится в SKL-10.
- AUD-03: floor-support актуален только для последнего завершённого движения с тем же pose/up. Смена поля, телепорт и другие изменения позы не дают прыжок от старой опоры.
- AUD-04: старый/повторный тик отклоняется до потребления наблюдения/нажатий и не приводит актуаторы в действие.
- AUD-05: архив ограничен 128 исходами, есть счётчики. После 10000 crossings сохраняются 128 записей, IDs монотонны; reset очищает архив/счётчики/recovery-state.
- AUD-06: `tools/check.ps1` включает обычную cadence и 30/144; CI запускает игровой smoke внутри экспортированного бинарника и сохраняет Windows/Linux-дистрибутивы с notices и manifest.

- До исправлений: физические пробы давали 7 падений (бок плиты/стопки в двух ориентациях, два варианта смены поля, recovery в стену). После — 13/13 исходных проверок; затем добавлены две регрессии очистки контактов возвращаемого тела, обе проходят (всего 15/15). Тест восстановления дополнительно проверяет отказ пути к ранее свободной позе и запрос reset.
- Контракт повторных тиков до guard: 3 падения; после — 4/4, включая reset.
- Полный набор при `--fixed-fps 30`: **315/315**. С обычной cadence: **315/315**, 202400 мс; при 144: **315/315**, 52025 мс.
- Linux release экспортирован; **12/12** игровых smoke-проверок: настоящий export template, тесты исключены из pack, меню, физические E/W/мышь, перенос/бросок, пауза, реальная нагрузка → сеть → дверь, перенос связки через портал, бросок в рамке выхода, автоматический reset при неисправимой геометрии. ## Экспорты и происхождение

`tools/export.ps1` пишет `builds/build-manifest.json`: schema_version, source_commit, source_tree, точная версия Godot, SHA256 игровых бинарников и Windows console wrapper. Неизвестные untracked игровые ресурсы и грязное tracked-дерево отвергаются, чтобы manifest не описывал другую сборку. Артефакты GitHub Actions называются `evacuation-windows-<checkout SHA>` и `evacuation-linux-<checkout SHA>`, хранятся 14 дней и содержат соответствующий бинарник (Windows также console wrapper), manifest, MIT/third-party notices и лицензии. В PR workflow checkout SHA может быть тестовым merge-коммитом; manifest фиксирует фактически собранный checkout, а не угаданный head PR.

Smoke включается только явным `--runtime-smoke`; в обычной игре диагностический узел не создаётся. Release-template Godot не поддерживает editor-only `--script`, поэтому запуск идёт через явный opt-in Bootstrap внутри того же игрового бинарника. Проверяется встроенный game pack; тестовый набор не включён в дистрибутив.

## Приёмка на целевом ПК — TD-08 открыта

1. Скачать Windows-артефакт из успешного workflow текущего PR; проверить SHA256 `evacuation.exe` по manifest. Распаковать рядом notices и `content/licenses`.
2. CPU-проверка экспортированной Windows-игры: `./evacuation.console.exe --headless --fixed-fps 144 -- --runtime-smoke`; нужен `EXPORTED_GAMEPLAY_SMOKE_PASSED` и exit 0. Это отдельное свидетельство Windows runtime; Linux-сборка его не заменяет.
3. Запустить игру с Vulkan и обновлённый `tools/portal_smoke.gd` через закреплённый редактор; проверить оба направления/края/близкий косой взгляд/полукуб, вперёд и спиной с кубом, отпускание/бросок, блокировки, питание, пол/потолок/поле, reset.
4. Записать GPU/драйвер, разрешение, профиль Source/2K, комфорт, FPS/время кадра и p95 по F3/F4. Проверить реальный ввод и переходы pause/focus.

В текущей среде нет X11/Wayland display. Новый Vulkan-smoke, RTX-производительность, Windows runtime и ручное прохождение не объявляются выполненными. Стабилизация кода не закрывает SKL-09, 0.1.0 и TD-08 целиком.

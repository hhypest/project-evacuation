# Исправления по тестированию владельца — 2026-11-10

Основа: main `34ed6ec`, merge PR №44. Свидетельства владельца: запись 3 мин 31 с, два снимка портального вида и журнал с тремя `CHAMBER_RECOVERY` для `portal.cube.a`/`portal.cube.heavy`. Сами пользовательские видео, снимки и локальные пути не включены в репозиторий. Решение — [ADR-0015](../adr/0015-playtest-native-portals-and-clearance.md).

## Что изменилось

| Сообщение владельца | Причина и результат |
| --- | --- |
| Размытие при повороте вблизи портала | Ограничивающий прямоугольник смещённой пирамиды теряет плотность пикселей при косом взгляде. Теперь камера получает полный преобразованный взгляд, мембрана выбирает экранный пиксель, а выходная геометрия отсекается отдельно. Увеличение разрешения всего прежнего прямоугольника не используется как замена исправлению. |
| Самопроизвольный reset с кубом | Возврат отказавшего спутника мог упираться в его собственного носителя. Теперь известная пара носитель/предмет использует проверенную политику отпускания с временным исключением взаимной коллизии до разделения. Стены/другие тела и коридор возврата проверяются; настоящий аварийный reset сохранён. |
| Куб «отлипает» от кнопки только после движения камеры | При точном контакте точки Jolt совпадают и дают нулевой вектор разделения. Адаптер получает нормаль контакта отдельно, освобождает обычный clearance и продолжает прежний sweep. Одно E начинает перенос без движения взгляда. |
| Куб у границы зоны мешает ориентации | Проверка только поворота вокруг центра не искала свободное место рядом. Добавлен ограниченный поиск позы с проверкой переноса и промежуточных ориентаций; кубы 0,75/1 м больше не удерживают прежнюю вертикаль. Действительно тесный коридор остаётся непроходимым для поворота. |
| F3/F4 недоступны | Узлы диагностики отсутствовали в обычном release без `--profile`. Теперь клавиши являются явным включением; скрытая панель ничего не измеряет. Добавлен приём logical keycode функциональных клавиш. |

## Воспроизводимые пробы

Начальная физическая проба на production-коде до исправления дала **пять отказов**: три расстояния захвата с плиты, блокировка поворота кубом и отказ вставленного спутника рядом с носителем. [Журнал до](playtest-2026-11-10/physical-before.txt). После исправления расширенный набор проверяет также метровый куб, явное отпускание в момент отказа, тяжёлый куб, 12 повторных проходов с каждым из двух кубов и жизненный цикл визуальных копий — [журнал после](playtest-2026-11-10/physical-after.txt). Эти пробы включены в обычный runner через `PlaytestRegressionTests`, а не оставлены отдельным ручным скриптом.

Новый тест проекции сравнивает одинаковые лучи основной и портальной камер после полного преобразования. Ошибка нормализованных координат в локальной пробе — менее 0,000001. Отдельно проверены передняя/задняя/пересекающая геометрия, добавление и удаление render-only копии, отсутствие второй физики/повторной тени и невидимость копии для основной камеры.

## GPU: близкий поворот

Windows, RTX 4070 Ti SUPER, Vulkan 1.4.351, Forward+, официальный Godot `4.7.2.stable.official.ed1daf0bf`, 1280 × 720, Source-текстуры. Глаза находятся в 3 см от плоскости. Один и тот же контрастный узор, положение камеры и код измерения использованы до/после; нет подмены снимками разных стендов.

| Yaw | Контрастные границы до | После, сторона A |
| --- | ---: | ---: |
| 10,3° | 246 | 165 |
| 37,2° | 46 | 148 |
| 60,2° | 12 | 116 |
| 71,6° | 20 | 107 |

Это число перепадов яркости > 0,12 на трёх строках, а не универсальная оценка качества или PSNR: исходная проекция даёт другой рисунок алиасинга при малом yaw. Существенный результат — сохранение различимых деталей на косых углах, где прежде они исчезали. [До, 60°](playtest-2026-11-10/before-60deg.png), [после, 60°](playtest-2026-11-10/after-60deg.png); [измерения до](playtest-2026-11-10/quality-before.txt), [после](playtest-2026-11-10/quality-after.txt).

`tools/portal_view_smoke.gd` проверяет четыре угла у **обоих** порталов, native target, сохранение PNG и ненулевой exit при потере деталей: `PORTAL_NATIVE_PASSED`. Обычный `tools/portal_smoke.gd` также проходит: оба направления, близкий вид, половины куба, проход игрока с кубом и бросок после перехода. Общий `tools/gpu_smoke.gd` проходит движение, перенос/постановку/стопки, устройства и гравитацию. `tools/profiler_smoke.gd` — `PROFILER_SMOKE_PASSED`, четыре строки CSV с реальными GPU-таймерами.

Отдельная GPU-проверка освещённого пола даёт яркость 0,251 (порог отказа 0,04): чёрные поверхности из-за маски источников света считаются ошибкой. Визуально осмотрены оба вида и половинки куба; добавлены проверки восстановления слоёв и удаления копий.

## Release и CPU

Windows release собран и запущен на Vulkan/RTX **без `--profile`**. Встроенный `--runtime-smoke` проходит **16/16**: в том числе F3 открывает панель, F4 начинает/останавливает локальный CSV; движение, пауза, нагрузка→сеть→дверь, портал и настоящая аварийная геометрия продолжают работать. Маркер этого smoke `CPU_ONLY` относится к проверкам игрового состояния; само изображение подтверждается отдельными GPU-прогонами выше.

Финальный `tools/check.ps1`: **343/343** при обычной cadence (249516 мс), 30 (18640 мс) и 144 (166971 мс). Типы/слои: 140 скриптов, 93 production-скрипта, ошибок/предупреждений нет. Отрицательные exit-code/argument проверки runner проходят. Документация: 96 Markdown-файлов, 867 локальных ссылок, 430 прежних якорей, ошибок нет; `git diff --check` проходит.

Обычный Windows release дополнительно открыт без аргументов запуска через компьютерный инструмент; меню работает. До подтверждения клавиши F3 пользователь остановил управление физическим Esc. Дальнейший ввод через компьютерный инструмент не выполнялся; аппаратная клавиатурная приёмка этим действием не объявляется выполненной. Проверка 16 сценариев выше использует настоящий release-pack и игровые события Input.

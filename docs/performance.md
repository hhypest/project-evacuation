Это инструменты разработки для сравнения сцен и графических ресурсов. Экранная панель не является финальным игровым интерфейсом (ADR-0004). Она не меняет движение, физику, паузу или управление мышью.

## Быстрый запуск

В редакторе Godot, debug- и обычной release-сборке:

- **F3** — показать/скрыть панель.
- **F4** — начать/остановить запись CSV; панель открывается автоматически.
- Если панель скрыта во время записи, запись продолжается. Без панели и записи сбор показателей и GPU-таймеры отключены.
- Пауза и потеря фокуса сохраняют обычные правила сессии. Профилировщик сам не продолжает игру.

Для запуска из PowerShell задайте `GODOT_BIN` путём к закреплённому Godot 4.7.2 либо передайте `-GodotPath`. Из корня проекта:

```powershell
./tools/profile.ps1
```

Сразу выбрать 2K и запустить игру:

```powershell
./tools/profile.ps1 -Quality 2K
```

В выпускной сборке панель и запись изначально выключены; F3/F4 доступны без параметров запуска. Чтобы сразу открыть панель:

```powershell
./builds/evacuation.exe -- --profile
```

## Переход на 2K и возврат исходного качества

Закройте игру и редактор перед сменой профиля. Затем:

```powershell
./tools/set_texture_quality.ps1 -Quality 2K
```

Команда ограничивает импорт **27 карт девяти комплектов**: куба, напольной и настенной кнопок, рубильника, логической панели, эмиттера, приёмника, створки и рамы двери. Все карты становятся не больше 2048 × 2048. Исходные изображения не переписываются, повторная генерация Meshy не требуется. Нормали, VRAM-сжатие и mipmaps сохраняют свои настройки. После импорта отдельный процесс Godot проверяет реальные размеры всех `Texture2D`.

Вернуться к исходным картам (цвет/нормали 4096, metallic/roughness 2048):

```powershell
./tools/set_texture_quality.ps1 -Quality Source
```

Либо одновременно восстановить и запустить:

```powershell
./tools/profile.ps1 -Quality Source
```

При ошибке настройки восстанавливаются и выполняется обратный импорт. Меняются только `.import` выбранных карт и ресурс `content/definitions/device_texture_quality.tres`. Это профиль импорта/сборки, а не переключатель уже загруженных ресурсов: после изменения перезапустите игру; для отдельного экспорта 2K примените профиль до `tools/export.ps1`. По умолчанию в репозитории выбран **Source**. Остальные текстуры проекта не изменяются.

Механизм основан на [`process/size_limit` импортера Godot](https://docs.godotengine.org/en/4.7/classes/class_resourceimportertexture.html#class-resourceimportertexture-property-process-size-limit). Даже в 2K-экспорте исходные файлы репозитория остаются доступными для возврата качества; размер checkout не уменьшается.

## Что показывает панель

| Показатель | Значение |
| --- | --- |
| FPS, средний кадр | По реальным интервалам между кадрами, включая ожидание VSync/лимита FPS |
| p95, max | 95-й процентиль ближайшим рангом и худший кадр за окно около 0,5 с; это не статистика всего сеанса |
| Процесс / физика | Последние значения встроенных мониторов Godot, мс |
| Отрисовка CPU / GPU | Среднее за окно: времена всех зарегистрированных активных viewport, включая порталы; CPU также включает setup кадра |
| Вызовы / примитивы | Глобальные счётчики отрисовки |
| Текстуры / видео | Оценка памяти ресурсов по счётчикам Godot, MiB; не полная занятость памяти видеокарты |
| Память движка | Статические выделения Godot; в release недоступно и показано «н/д» |
| Профиль / сцена / размер | Source или 2K, путь уровня и разрешение окна |
| Пауза / фокус | Состояние при измерении, чтобы не смешивать его с обычным прохождением |

Окно сбрасывается при смене сцены, паузы или фокуса. При обычной публикации отметка последнего кадра сохраняется: задержки записи CSV, обновления панели и поиска viewport попадают в следующий интервал кадра. Буфер ограничен 4096 интервалами. Новые viewport обнаруживаются раз в окно, поэтому после загрузки нужна небольшая выдержка. Отключённые portal viewport не добавляют устаревшее GPU-время. GPU «н/д» или `-1` в CSV означает отсутствие измерения, а не нулевую стоимость.

Часть [мониторов Performance](https://docs.godotengine.org/en/4.7/classes/class_performance.html) обновляется с задержкой до секунды. [GPU/CPU-времена RenderingServer](https://docs.godotengine.org/en/4.7/classes/class_renderingserver.html#class-renderingserver-method-viewport-get-measured-render-time-gpu) относятся к отрисовке; при ограниченном FPS энергосбережение видеокарты также влияет на результаты. Для поиска дорогих методов GDScript используйте дополнительно встроенный [Debugger → Profiler](https://docs.godotengine.org/en/4.7/tutorials/scripting/debug/the_profiler.html).

## CSV и сравнение

Отчёты сохраняются локально в `user://profiles/`. В Windows это обычно `%APPDATA%/Godot/app_userdata/Project Evacuation/profiles/`. Точный путь печатается в консоли при старте записи; панель показывает имя файла. Отправки отчётов по сети нет. CSV — UTF-8, разделитель запятая; Excel может потребовать «Данные → Из текста/CSV».

Запись идёт примерно дважды в секунду и сбрасывается на диск после строки, при остановке и выходе. Есть версия Godot, GPU/renderer, сцена, профиль текстур, разрешение, VSync, лимит FPS и частота физики. `elapsed_s` — время с запуска диагностического узла, не длительность записи.

Для сравнения Source/2K выберите один уровень, одинаковые разрешение/VSync/лимит кадров и положение камеры. Дайте сцене прогреться около 10 секунд, затем запишите одинаковый маршрут 30–60 секунд. Отдельно сравнивайте обычную сцену и активные порталы. Маленький GPU-smoke подтверждает работоспособность инструмента, но не заменяет такой замер.

Проверки и короткое сравнение на RTX — [QA](qa/profiler-texture-quality-2026-11-09.md).

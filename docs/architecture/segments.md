# Подгрузка сегментов: проектные принципы

**Целевая схема, не реализована.** Приняты бесшовный сектор и шлюзы; детальный протокол требует нового ADR и прототипа. Бюджеты ниже — стартовые кандидаты. Они не расширяют проверенную границу одной портальной пары из [архитектуры](portals.md) без профилирования и решения.

## 8. Техника: подгрузка сегментов

Сейчас `LevelScope` держит один уровень, и новый уровень открывает новый scope. Для бесшовного сектора нужен небольшой шаг вперёд. Это архитектурное изменение, под него стоит написать ADR.

- **Сегмент** — сцена плюс `LevelDefinition`. У сегмента есть входной и выходной шлюзы с якорями (Marker3D) для стыковки.
- **Окно загрузки:** текущий сегмент + следующий. При входе в шлюз:
  1. дверь за спиной закрывается;
  2. предыдущий сегмент выгружается;
  3. стартует `ResourceLoader.load_threaded_request` для сегмента после следующего (или следующего, если ещё не загружен);
  4. дверь вперёд открывается, только когда сегмент готов (звук шлюза маскирует ожидание).
- **Шлюз — граница scope.** Команды старого сегмента игнорируются по `scope_id`, как и сейчас. Состояние камеры не переживает выход из неё: камера решена и закрыта.
- **Сохранение камеры** привязано ко входу и к авторским контрольным точкам внутри неё. Ручной `reset` пересоздаёт камеру со входа.
- **Координаты:** сегменты стыкуются по якорям шлюзов. Сектор целиком в мировых координатах может быть большим (сотни метров по вертикали), это нормально для float32 до ~2–4 км. Если нужно — сдвигать начало координат на шлюзах.

### Бюджеты производительности (стартовые, мерить на целевом железе)

| Бюджет | Камера | Переход |
| --- | --- | --- |
| Видимых треугольников | ≤ 1.5 млн | ≤ 2–3 млн (с дальним поясом) |
| Источников света с тенью в кадре | ≤ 6–8 | ≤ 4–6 (фонарь + 3–5) |
| Динамических тел | ≤ 12 | ≤ 20 (пропсы, без участия в задачах) |
| Активных пар порталов | Кандидат до 2 после профилирования; текущая начальная граница — 1 пара | 0–1 |
| Окклюдеры | Обязательно у стен шлюза | Обязательно на поворотах и в узких ходах |

Свет в камерах — ровный, лучше запечённый (LightmapGI или VoxelGI). Игровые сигналы — эмиссия и маленькие источники без теней (ADR-0006).

# План переработки документации

Задача владельца от 2026-11-10: снизить когнитивную нагрузку всей документации. В PR №39 подготовлен план; перенос и переписывание выполняются следующими задачами DOC-01…DOC-05. Их состояние ведётся в [status.md](../../status.md#переработка-документации).

Результат: читатель выбирает свою задачу, получает короткую инструкцию и открывает подробности по необходимости. Требования игры, канон, ID задач и достоверные свидетельства проверок сохраняются.

## Что мешает сейчас

Снимок ветки PR №39 до этих правок: 48 Markdown-файлов. Readme — 341 строка, Architecture — 417, CONTRIBUTING — 236. Длина сама по себе не дефект; проблема в смешении назначения и обязательного маршрута чтения.

- [Readme](../../../Readme.md) объединяет описание игры, требования, запуск, полный план версий, риски и источники. Для первого запуска приходится отсеивать сведения о будущем производстве и выпуске.
- [Architecture](../../../Architecture.md) совмещает целевую модель и текущую реализацию; [CONTRIBUTING](../../../CONTRIBUTING.md) повторяет часть архитектурных правил и команд проверок. Читателю приходится сверять несколько текстов.
- [Индекс лора](../../design/lore/README.md) открывается разбором редакции 2, хотя канон уже в [библии](../../design/lore/world-bible.md), а художественный текст — в редакции 4. Старые открытые вопросы и статусы могут выглядеть актуальными.
- В таблице документов на входе лор, чек-лист, инструкции и отчёты стоят на одном уровне. Нет коротких маршрутов «запустить», «внести изменение», «собрать камеру», «найти принятое решение».
- Найденные Codex расхождения в направлении сектора и дальности прыжка показывают риск нескольких источников одного правила. Они исправлены в этом PR; другие расхождения нужно выявлять инвентаризацией, а не молча согласовывать редактурой.

## Как читатель будет входить

Readme остаётся краткой обложкой проекта: что это, состояние со ссылкой, первый запуск, лицензия и четыре маршрута. Подробный каталог находится в будущем `docs/README.md`; страницы открываются обычным Markdown на GitHub и локально.

| Задача читателя | Первый документ | Дальше только по необходимости |
| --- | --- | --- |
| Запустить игру и проверить управление | `docs/getting-started.md` | Проверка механик, диагностика производительности |
| Внести изменение | CONTRIBUTING | Архитектура, нужная инструкция и матрица проверок |
| Спроектировать камеру или сцену | `docs/design/README.md` | Ритм, метрики, карточка камеры, постановка, канон |
| Узнать состояние и следующее действие | `docs/status.md` | `docs/roadmap.md`, принятое решение или QA-свидетельство |

Новые пути здесь — проект структуры, пока не действующие ссылки. Readme целится в 80–120 строк без подробных таблиц всех версий. Страница инструкции начинается с результата и предпосылок, затем даёт шаги, проверку успеха и частые отказы. Справочник начинается с краткого ответа и оглавления. Нормативное правило имеет один основной источник; другие страницы дают краткое пояснение и ссылку.

DOC-03 и DOC-04 независимы после DOC-02. Это отдельный поток документации рядом с инженерным roadmap: он не закрывает SKL/ART/LVL и не меняет их зависимости. Начинать с DOC-01; оценку следующих этапов уточнить по инвентаризации, календарных сроков до неё нет.

Каждый этап — отдельный связный PR. Сначала создаются новые страницы и исправляются ссылки, затем сокращаются старые. Для перемещённых страниц оставляют указатели со старых путей; для старых заголовков сохраняют якоря или явную совместимость. В том же PR обновляют AGENTS, обратные ссылки, status и changelog. Удаление дубликата подтверждается картой «старый раздел → основной источник».

## Как проверить снижение нагрузки

- От Readme до инструкции каждого из четырёх маршрутов — не больше двух переходов. Новичку не нужно читать лор, ADR и QA перед первым запуском.
- Владелец и участник, не делавший перенос, находят за две минуты каждый: команду запуска, нужную проверку изменения, правила сборки камеры, источник канона и следующий незавершённый шаг. Фиксируются маршрут, время, ошибочные переходы и потребовавшиеся подсказки. Если участника пока нет, проверка остаётся открытой.
- Первый запуск воспроизводится по новой инструкции из чистого checkout: закреплённый инструментарий, импорт, меню и один стенд. Записываются ОС и версия; успех на одной ОС не объявляется проверкой другой.
- Все локальные пути и якоря проверены с учётом регистра; внешние ссылки проверяются отдельно. Нет новых битых ссылок; старые проблемы перечислены. Инструкции не ведут на ещё не созданные страницы.
- Матрица переноса подтверждает сохранение требований, канона, ID/зависимостей roadmap, ограничений проверок, лицензий и QA-свидетельств. Редактура не объявляет предложение принятым или задачу выполненной.
- Каждая актуальная страница отвечает на одну основную задачу. Подробности доступны по ссылке; длинный справочник имеет краткое резюме и оглавление. Число файлов или сокращённых строк само по себе не считается успехом.

Если в DOC-01 обнаружится конфликт двух принятых решений, требуется конкретное решение владельца. Рутинные переносы, редактура, навигация и устранение повторов выполняются в рамках этой задачи; результат полного переустройства принимается после DOC-05.

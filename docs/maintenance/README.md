## Порядок изменения

1. Выбрать основной источник из таблицы; менять правило там. Другие страницы дают короткое объяснение и ссылку, а не вторую полную инструкцию.
2. Писать для одной задачи: результат, предпосылки, шаги, проверка успеха и ожидаемые отказы. У длинного справочника — краткое резюме и оглавление.
3. Отмечать принятый факт, целевой контракт, предложение и историческое свидетельство. Не закрывать задачу наличием концепта или нового текста.
4. При переносе сохранить старый путь и якоря указателем, обновить входящие ссылки и `migration-map.json`; проверять ссылки в том же PR. Сначала создаётся новое место, затем сокращается старое.
5. Обновить status, changelog и затронутые указатели. Документ с временным планом после выполнения должен отражать фактический остаток.
6. Запустить `python tools/check_docs.py` из checkout (Python 3.10+, без пакетов). Сверить команды с tools и workflow. Внешние адреса получить флагом `--external-list` и проверить отдельно; причину сетевого отказа записать.
7. Если менялась установка/запуск, воспроизвести из чистого checkout на указанной ОС. Новые маршруты проверить без знания расположения файлов; человеческую приёмку не заменять собственным просмотром автора.

## Что сохраняется

Не удалять требования, ID/зависимости задач, канон, лицензии или ограничения QA ради краткости. Старые отчёты не переписывать под сегодняшнее состояние. Архивировать с датой, причиной и ссылкой на действующий источник. Обновление движка, схемы сохранения или бюджета порталов — отдельное решение с проверкой, не редакционная правка.

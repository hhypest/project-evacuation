# ADR-0003: JSON как формат сохранения прогресса

- Статус: принято. Вход и станции SKL-10 реализованы
- Дата: 2026-11-07
- Задачи: SKL-10, SYS-04, CMP-04

## Контекст и решение

Прогресс хранится в UTF-8 JSON в папке `saves` рядом с исполняемым файлом игры. При запуске исходного проекта папка создаётся в его корне. Папку создаёт первая запись. Если каталог недоступен, меню показывает ошибку сохранения.

Текущая схема 2 расширяет четыре поля схемы 1.

| Поле | Значение |
| --- | --- |
| `schema_version` | Целое число 2 |
| `game_version` | Версия сборки игры |
| `level_id` | Стабильный ID уровня из каталога |
| `checkpoint_id` | `entry` или стабильный ID станции в каталоге уровня |
| `completed_levels` | Список уникальных ID завершённых камер |
| `switches` | ID разрешённых точкой переключателей и их логические состояния. Для входа пустой объект |

Запись происходит после успешного открытия камеры из меню, на станции по E и при завершении камеры. Станция разрешает запись, когда её условия выполнены. При загрузке игра находит уровень и точку по устойчивым ID. Станция задаёт положение и взгляд игрока. Кубы возвращаются на предусмотренные места, сеть пересчитывает сигналы после восстановления переключателей. Таймеры, давления на плиты, скорости тел, перенос и переходы портала начинаются с нового состояния сцены.

Схема 1 читается как точка входа с пустым прогрессом. Старый файл остаётся на диске. Запись схемы 2 создаёт новое поколение. Выбор той же камеры для нового прохождения и R сохраняют существующую станцию на диске. Отметка о завершении обновляется в той же контрольной точке.

## Граница архитектуры

Application определяет типизированные `SaveSnapshot`, `SaveResult` и порт `SaveRepository`. Infrastructure отвечает за файлы, JSON и проверку структуры. Идентификаторы задаются в контенте. Экземпляры узлов, ресурсы и дескрипторы физики остаются в рантайме. Настройки управления, графики и звука находятся вне этой схемы.

## Проверка и последствия

Адаптер записывает временный файл в `saves`, закрывает и перечитывает его для проверки, затем публикует под новым именем `checkpoint-*.json`. Переименование в новое имя сохраняет предыдущее исправное поколение на Windows. Повторная запись одинаковой точки, версии и прогресса использует уже записанный файл. Чтение пропускает временные файлы и ищет последнюю исправную запись при повреждении JSON. Если последняя запись использует более новую схему, адаптер прекращает загрузку и оставляет её на диске.

Первый этап проверяет чтение и запись, повреждённый JSON, неверные типы, недоступный путь, прерванную запись и открытие камеры после загрузки из меню. В SYS-04 запланированы миграции, проверки устойчивости записи на целевых ОС и политика хранения поколений.

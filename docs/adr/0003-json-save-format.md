# ADR-0003: JSON как формат сохранения прогресса

- Статус: принято по прямому требованию владельца; реализация впереди
- Дата: 2026-11-07
- Задачи: SKL-10, SYS-04, CMP-04

## Контекст и решение

Владелец зафиксировал формат будущих сохранений — **JSON**. Прогресс хранится в UTF-8 файлах `*.json` в `user://saves/`, с обязательной версией схемы. Выбор бинарной сериализации Godot в качестве основного формата прогресса не соответствует требованию.

Точный контракт определяется в SKL-10. Он включает `schema_version`, версию игры, стабильные ID уровня/checkpoint и данные прогресса. JSON содержит обычные значения и явно описанные структуры; Node, Resource, handles физики и строковые представления объектов Godot не сохраняются.

## Граница архитектуры

Application работает с типизированным `SaveSnapshot` и портом `SaveRepository`. Файлы, JSON-кодирование, проверка структуры и миграции реализуются в Infrastructure. Разобранные словари не передаются в Domain/Application. Формат настроек остаётся отдельным решением; это требование фиксирует именно сохранения прогресса.

## Проверка и последствия

В SKL-10 нужен рабочий JSON round-trip безопасной контрольной точки. SYS-04 добавляет fixtures миграций, повреждённого синтаксиса, неверных типов/диапазонов и неизвестной версии, резерв и проверяемую на целевых ОС атомарную замену. Неизвестная схема даёт безопасный отказ; повреждённый файл сохраняется для восстановления.

Политика сохранения на контрольных точках сохраняется. JSON не означает автоматическую поддержку произвольного quicksave. В текущей 0.0.2-dev сериализатор ещё отсутствует; этот ADR не объявляет сохранения реализованными.
